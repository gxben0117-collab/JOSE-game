# 戰鬥畫面升級 — 可行性分析與五方案

日期：2026-07-12
作者：Claude Code（供決策後交 Codex 執行）

## 一、現況診斷

- 技術棧：純靜態 HTML/JS + 自託管 Three.js，全部遊戲邏輯約 40KB（`js/v2/`）。
- 模型：45 隻 Quaternius「Ultimate Monsters」CC0 GLB（低多邊形卡通風），含 Idle/Run/Attack/Hit/Death/Victory 骨架動畫。
- 戰鬥場景（`js/v2/renderer3d.js`）：一個圓形地板 + 兩盞燈 + 漂浮小粒子，鏡頭固定。**「隨便」的主因不是模型，是演出工程幾乎為零**：沒有運鏡、沒有 hit-stop、沒有技能分鏡、沒有場景美術。

## 二、能不能做到「現行手遊同級」？（誠實版）

| 目標 | 判定 | 理由 |
| --- | --- | --- |
| 流暢度（60fps、打擊感、動作銜接） | **可以，100%** | 這是純工程問題。Pixi/Phaser/Three 在瀏覽器都跑得到 60fps；打擊感（hit-stop、震動、殘影、傷害數字、預備動作）全是程式可寫的。 |
| 畫面精緻度（3D 路線） | **到頂約「小品手遊」** | 免費 3D 模型的天花板就是 Quaternius/KayKit 這種低多邊形卡通風，現在已經在用了。要《原神》級 3D 是上億美術預算，不可能。 |
| 畫面精緻度（2D / 2.5D 路線） | **可逼近《劍與遠征》《神魔之塔》觀感** | 免費 2D 資產生態遠比 3D 豐富，且 AI 生圖已能產出商業級 2D 立繪——你已經有 AI 生圖 + 去背產線（LINE 貼圖專案），這是我們最大的槓桿。 |

**結論：流暢度沒問題；精緻度要達標，2D/2.5D 是對的方向，關鍵資產靠「AI 生成 + 免費資產庫」雙軌。**

## 四、五方案

### 方案一：3D 強化版（保留現有一切，只做演出工程）
- 做法：留 Three.js + 45 隻模型。加卡通渲染（toon shading + 外描邊）、bloom 後製、動態運鏡（攻擊時推近、必殺技環繞）、hit-stop、殘影、地面材質與天空盒（AI 生成貼圖）、技能分鏡。
- 畫面上限：★★☆☆☆（小品手遊）｜工作量：★★☆☆☆（1~2 週）｜風險：最低
- 適合：想先「立刻明顯變好」再決定要不要換路線。

### 方案二：2.5D 混血（3D 角色 + 2D 精緻場景與 UI）
- 做法：鏡頭改斜 45° 固定視角（AFK Arena 式），戰鬥背景換成 AI 生成的精緻 2D 場景大圖，3D 角色站在其上；UI 全面重做成手遊質感。
- 畫面上限：★★★☆☆｜工作量：★★★☆☆（2~3 週）｜風險：中（3D 角色與 2D 背景的光影融合要調）
- 適合：想保留 45 隻模型與動畫的投資，但大幅拉高整體觀感。

### 方案三：精緻 2D 立繪 + 程式骨骼動畫（⭐ 推薦）
- 做法：用 AI 生成 45 隻**一致風格**的怪物立繪（訂一份風格 prompt 模板），去背後分層（身體/前肢/眼睛），改用 **Pixi.js**（WebGL 2D，效能好、純靜態可用）做呼吸起伏、攻擊位移、squash & stretch、受擊閃白、打擊特效幀動畫。戰鬥版面照《劍與遠征》三對三橫排。
- 畫面上限：★★★★☆（最接近現行 2D 手遊）｜工作量：★★★★☆（3~5 週，大頭在 45 隻生圖與分層，可用貼圖專案的產線批次做）｜風險：中（AI 風格一致性要靠 prompt 模板 + 人工挑圖）
- 適合：目標就是「跟現行手遊同級的精緻度」時的正解。

### 方案四：高品質像素風 2D
- 做法：改像素美術路線（《坎公騎冠劍》風），直接用 itch.io/CraftPix 的現成像素怪物包（自帶逐幀動畫），Pixi/Phaser 驅動 + CRT/發光濾鏡。
- 畫面上限：★★★★☆（像素風裡的精緻）｜工作量：★★★☆☆（2~4 週）｜風險：低偏中（45 隻怪要遷就現成資產重新對應設定；風格是否喜歡是主觀門檻）
- 適合：想用「現成資產就很精緻」的最短路徑，且能接受像素風。

### 方案五：卡牌演出型（輕動作、重演出）
- 做法：戰鬥改回合制卡牌式（神魔之塔/陰陽師演出邏輯）：大張立繪 + 技能 cut-in（角色頭像橫切畫面）+ 全螢幕技能特效 + 數字與連擊演出。角色不需要跑打動畫，只要立繪動態（浮動、發光、震動）。
- 畫面上限：★★★★☆（精緻度全押在立繪與特效）｜工作量：★★★☆☆（2~3 週，但戰鬥玩法要重設計）｜風險：中（玩法會變，不只是換皮）
- 適合：接受戰鬥從「動作演出」轉向「策略回合＋華麗演出」。

## 五、建議

1. **首選方案三**，理由：精緻度上限最高、AI 生圖產線現成、Pixi.js 符合零打包約束。
2. 若想低成本先驗證，**先做方案一**（演出工程那套 hit-stop/運鏡/特效程式碼，之後搬到方案三照用，不白做）。
3. 方案三+五 可合併：先做三的橫排即時戰，之後把必殺技加上五的 cut-in 演出。

## 六、決策後的執行切分（給 Codex）

- 第一步一律先做「打擊感工程包」：hit-stop、鏡頭/畫面震動、傷害數字、受擊閃白、技能音效槽——任何方案都用得到。
- 資產先行：選定方案後先產 6 隻怪的資產跑通整條產線（生圖→去背→分層→進遊戲），驗收風格再批次做完 45 隻。
- 每批資產入庫前更新 `docs/3D_ASSET_LICENSES.md`（改名為資產授權清單，涵蓋 2D）。
